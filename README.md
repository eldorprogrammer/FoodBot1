# Foodbot — Telegram-бот доставки еды

Бот для заведения: полное меню с категориями, корзина, оформление заказа
(оплата при получении или онлайн через Telegram Payments), история заказов
клиента и встроенная админ-панель для управления меню, наличием блюд
и статусами заказов.

## Возможности

**Клиент**
- Регистрация сразу при первом `/start`: имя, телефон (можно кнопкой «отправить
  контакт»), адрес доставки по умолчанию. Пока анкета не заполнена, доступ
  к меню/корзине/заказам закрыт — бот вежливо предложит сначала зарегистрироваться
- Просмотр меню по категориям, с фото, описанием и ценой
- Блюда, которых нет в наличии, помечаются ⛔ и недоступны к заказу —
  статус обновляется мгновенно, как только админ меняет наличие
- Корзина: изменение количества, удаление позиций
- Оформление заказа: адрес, телефон, комментарий, выбор оплаты
- Оплата при получении или онлайн (Telegram Payments / ЮKassa / Stripe и т.д.
  — любой провайдер, подключаемый через @BotFather)
- История заказов со статусами и уведомления при смене статуса

**Админ-панель** (доступна пользователям из `ADMIN_IDS`, а также через
кнопку «🔐 Админ-панель» в главном меню бота по логину и паролю
из `ADMIN_LOGIN` / `ADMIN_PASSWORD`)
- Категории: создание, переименование, удаление
- Блюда: добавление (название, описание, цена, фото), редактирование,
  удаление, переключатель **«в наличии / нет в наличии»**
- Заказы: список активных, просмотр состава, смена статуса
  (новый → принят → готовится → в доставке → выполнен, либо отмена)
  с автоматическим уведомлением клиента
- Статистика: количество заказов и выручка за сегодня

## Стек

Python 3.11+, aiogram 3, SQLAlchemy 2 (async). База данных — SQLite «из коробки»
(файл, без установки чего-либо) либо любая внешняя PostgreSQL (Neon, Supabase,
свой сервер и т.д.) — просто через `DATABASE_URL`.

## Установка

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. (Опционально, для онлайн-оплаты) В @BotFather → Payments подключите
   платёжного провайдера и получите provider token.
3. Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) —
   он понадобится для `ADMIN_IDS`.
4. Установите зависимости:
   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```
5. Скопируйте `.env.example` в `.env` и заполните:
   ```bash
   cp .env.example .env
   ```
   По умолчанию используется SQLite — ничего дополнительно поднимать не
   нужно, файл базы создастся сам. Если хотите использовать внешнюю
   PostgreSQL (например, Neon), укажите её строку в `DATABASE_URL` — см.
   комментарий в `.env.example`.
6. Запустите бота:
   ```bash
   python bot.py
   ```
   При первом запуске таблицы создаются автоматически.

## Первые шаги после запуска

1. Напишите боту `/admin` со своего аккаунта (из `ADMIN_IDS`), либо
   нажмите кнопку «🔐 Админ-панель» в главном меню и войдите по логину
   и паролю из `.env`.
2. Создайте категории («📋 Категории» → «➕ Добавить категорию»).
3. Добавьте блюда в каждую категорию («🍔 Блюда» → выбрать категорию →
   «➕ Добавить блюдо»).
4. Когда блюдо заканчивается — открываете карточку блюда и нажимаете
   «⛔ Снять с продажи»; когда снова в наличии — «✅ Вернуть в наличие».
   Клиенты сразу видят актуальный статус в меню.

## Структура проекта

```
foodbot/
├── bot.py                     # точка входа, регистрация роутеров
├── config.py                  # чтение .env
├── database/
│   ├── models.py               # таблицы: User, Category, MenuItem, Cart, Order...
│   ├── engine.py                # подключение к БД
│   └── crud.py                  # вся работа с БД
├── handlers/
│   ├── user/                    # старт, меню, корзина, оформление, история
│   └── admin/                   # категории/блюда/заказы/статистика
├── keyboards/                  # инлайн- и реплай-клавиатуры
├── middlewares/db.py            # сессия SQLAlchemy на каждое сообщение
└── states/states.py             # FSM-состояния диалогов
```

## Продакшн-заметки

- Для боевой эксплуатации замените `Base.metadata.create_all` (в `database/engine.py`)
  на миграции Alembic — так безопаснее менять схему без потери данных.
- Рекомендуется запускать бота как systemd-сервис (Linux) или как
  задачу автозапуска / Windows-службу (Windows) — с автоперезапуском
  при падении.
- Реквизиты (`BOT_TOKEN`, `PAYMENTS_PROVIDER_TOKEN`, пароль от БД) храните
  только в `.env`, не коммитьте в репозиторий.
- Если нужен приём заказов, когда бот временно недоступен, добавьте fallback
  на резервный номер телефона/менеджера в описании бота.

## Возможные доработки

- Геолокация клиента + расчёт стоимости доставки по зоне/расстоянию
- Промокоды и скидки
- Множественные точки/филиалы с разным меню и наличием
- Отдельная роль «курьер» с уведомлениями о новых заказах на доставку
- Веб-дашборд для владельца (текущая админ-панель — телеграм-based,
  этого чаще всего достаточно для одного заведения)
